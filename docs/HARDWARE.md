# Переход на реальные камеры

Конвейер не знает, откуда берутся кадры: он работает с интерфейсом `ISource`
(`include/wz/source.hpp`). Поэтому подключение железа сводится к одному классу,
а синхронизация, калибровка, склейка и веб-вывод остаются нетронутыми.

## Что нужно реализовать

В `src/source.cpp` есть класс `CameraSource` — сейчас его `open()` возвращает
ошибку с пояснением. Нужно заполнить два метода:

- `open()` — найти устройство по `cfg_.path` (индекс или системный идентификатор),
  выставить разрешение `cfg_.width` x `cfg_.height`, частоту `cfg_.fps`
  и формат MJPEG.
- `read()` — дождаться кадра, разобрать его и заполнить `Frame`.

Платформенные API: **Media Foundation** в Windows (`mfreadwrite.h`,
интерфейс `IMFSourceReader`), **V4L2** в Linux (`/dev/videoN`, `VIDIOC_*`).

## Два требования, которые нельзя нарушить

**1. Кадр приходит как JPEG — его не нужно распаковывать вручную.**
Камеры в режиме MJPEG отдают готовый JPEG. Достаточно передать буфер в
`loadImageFromMemory()`:

```cpp
if (!loadImageFromMemory(buffer, bufferSize, out.image, &err)) return false;
```

**2. Метка времени — момент съёмки, а не момент получения буфера.**
От этого напрямую зависит работа синхронизатора. Если драйвер отдаёт аппаратную
метку, её нужно привести к шкале `nowMicros()` (монотонные микросекунды
процесса); если не отдаёт — ставить `nowMicros()` сразу после возврата из
драйвера, до любой обработки.

```cpp
out.timestampUs = nowMicros();
out.sourceIndex = index_;
out.sequence = frames_++;
```

Метод `stamp()` из базового класса для реального устройства не подходит: он
вычисляет метку по номеру кадра, что верно только для файлов с постоянной
частотой.

## Настройка после подключения

1. Проверить, что камеры отдают кадры:
   `workzone_server --source camera:0 --source camera:1 --snapshot проверка.png`
2. Закрепить камеры окончательно. После любого сдвига калибровку нужно повторить.
3. Нанести на стол не менее четырёх меток и записать их координаты в миллиметрах.
4. Снять по кадру с каждой камеры, определить пиксельные координаты меток.
5. Заполнить файл соответствий (формат — `calibrate --help`) и выполнить:
   `calibrate --points config/points.json --out config/system.json`
6. Убедиться, что ошибка перепроецирования не превышает 1–2 мм.
7. Открыть карту покрытия в веб-интерфейсе и проверить, что зона наплавки
   попадает в перекрытие двух камер: только там убирается тень от головы.

## Параметры камеры (intrinsics)

Для устранения дисторсии нужны `fx`, `fy`, `cx`, `cy` и коэффициенты `k1`, `k2`.
Если паспортных значений нет, для начала подойдёт оценка по углу обзора
(`Intrinsics::fromFov`), а коэффициенты дисторсии подбираются так, чтобы прямые
линии на столе выглядели прямыми в панораме. Для точной работы параметры лучше
получить отдельной калибровкой по шахматной доске.

## Рассинхронизация

`sync.toleranceUs` задаёт допустимый разброс меток внутри набора. По умолчанию
20 000 мкс — примерно половина межкадрового интервала при 30 кадр/с. Если камеры
не синхронизированы аппаратно и в интерфейсе растёт счётчик отброшенных кадров,
допуск стоит увеличить; если важна одновременность — уменьшить и смириться
с потерями.

# Запуск с двумя камерами

## 1. Проверить, что система их видит

```bash
workzone_server --list-cameras
```

Должны появиться обе с режимами MJPG. Имена у одинаковых камер совпадают,
различать их можно только по символьной ссылке.

## 2. Запустить без калибровки

Пока гомографий нет, склеивать нечего, но смотреть на зону уже надо:

```bash
workzone_server --source camera:0 --source camera:1 --layout side-by-side
```

Камеры раскладываются по половинам холста. Работает синхронизация, веб-интерфейс,
запись снимков, настройки яркости — всё, кроме собственно склейки.
Интерфейс: http://127.0.0.1:8080/

## 3. Снять кадры для калибровки

```bash
workzone_server --source camera:0 --source camera:1 --layout side-by-side --grab data/shot
```

Получатся `data/shot_cam0.png` и `data/shot_cam1.png`. По ним определяются
пиксельные координаты меток, лежащих на столе в известных местах.

## 4. Откалибровать и запустить со склейкой

```bash
calibrate --points config/points.json --out config/system.json
workzone_server --config config/system.json --source camera:0 --source camera:1
```

Формат `points.json` — в `calibrate --help`.

## Привязка камер

Индекс `camera:0` зависит от порядка перечисления и меняется при перетыкании
кабеля. Чтобы левая камера не стала правой, указывайте кусок символьной ссылки
из `--list-cameras`:

```bash
workzone_server --source camera:2b17f6cf --source camera:289aedf9
```

## Останавливать только через Ctrl+C

Сервер корректно закрывает потоки камер: `requestStop()` вызывает `cancel()`,
тот делает `Flush()` и освобождает зависший `ReadSample`.

**Принудительное завершение (`taskkill /F`, «снять задачу») это обходит и
оставляет камеру в нерабочем состоянии.** Она перестаёт отдавать кадры с
ошибкой `0x8007001F` («устройство не функционирует») и не поднимается даже
в одиночку. Проверено дважды за одну сессию.

Восстановление — любой из вариантов:

- переткнуть кабель;
- сбросить устройство из PowerShell с правами администратора:

```powershell
Get-PnpDevice -Class Camera | Where-Object Status -ne 'OK' | ForEach-Object {
  Disable-PnpDevice -InstanceId $_.InstanceId -Confirm:$false
  Enable-PnpDevice  -InstanceId $_.InstanceId -Confirm:$false
}
```

## Нагрузка на шину

Две камеры лучше держать на разных USB-контроллерах. Проверка:

```powershell
Get-PnpDevice -Class Camera | ForEach-Object {
  (Get-PnpDeviceProperty -InstanceId $_.InstanceId -KeyName 'DEVPKEY_Device_Parent').Data
}
```

Разные значения до первого `&` означают разные контроллеры. На одном хабе
две камеры 1080p конкурируют за полосу и питание.

## Частота и синхронизация

Камеры не синхронизированы аппаратно, метка ставится по приходу кадра.
Сдвиг фаз постоянный, и если он превысит `sync.toleranceUs` (по умолчанию
20 мс), не сойдётся ни одна пара — счётчик «сведено наборов» останется нулём
при ненулевых счётчиках источников.

Запас по допуску равен периоду кадра: при 30 кадр/с это 33 мс, то есть допуск
может не хватить. Варианты: поднять `sync.toleranceUs` до 35000 либо перейти
на 60 кадр/с (`--size` оставить, в конфигурации задать `fps: 60`) — период
станет 17 мс и уложится в текущий допуск.
