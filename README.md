# Система камер для наблюдения рабочей зоны

Программно-аппаратный комплекс из нескольких камер, который сводит их потоки
в единую панораму «вид сверху» на рабочую зону лазерной наплавки и отдаёт её
в браузер.

Проект доводит до рабочего состояния задачи, перечисленные в отчёте как
незавершённые: временную синхронизацию потоков, программную сшивку, калибровку
камер и вывод собранного изображения на веб-платформу.

## Что умеет

| Задача из отчёта | Где решена |
|---|---|
| Захват нескольких потоков | `src/source.cpp` — сменные источники |
| Временная синхронизация | `src/sync.cpp` — сведение кадров по меткам времени |
| Калибровка объектива | `src/chessboard.cpp`, `src/intrinsics_calib.cpp` |
| Калибровка положения, устранение дисторсии | `src/calibration.cpp`, `apps/calibrate.cpp` |
| Проецирование на одну плоскость и склейка | `src/stitcher.cpp` |
| Устранение артефактов на стыке | растушёвка, выравнивание экспозиции, отбраковка перекрытий |
| Вывод потока на сайт | `src/http_server.cpp`, `web/index.html` |

Внешних зависимостей нет. Нужны только компилятор C++17 и CMake: декодирование
и кодирование JPEG берёт на себя `stb` из `third_party/`, вся математика
калибровки и склейки реализована в проекте.

## Быстрый старт

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Запуск на виртуальной сцене — работает сразу, камеры не нужны:

```bash
./build/workzone_server
```

Интерфейс откроется по адресу `http://127.0.0.1:8080/`.

### Работа с записями

Сгенерировать тестовые записи и конфигурацию под них:

```bash
./build/gen_testdata --out data --frames 120 --mjpeg
./build/workzone_server --config data/system.json
```

Свои записи подкладываются так же: каталог с кадрами (`jpegdir`) или файл
с потоком JPEG (`mjpeg`). Видео в MP4 предварительно разложите на кадры:

```bash
ffmpeg -i запись_левой.mp4 -q:v 3 data/cam_left/%06d.jpg
```

## Утилиты

| Программа | Назначение |
|---|---|
| `workzone_server` | конвейер и веб-сервер; `--snapshot файл.png` собирает один кадр и выходит |
| `gen_testdata` | генерация воспроизводимых записей виртуальной сцены |
| `calibrate` | построение гомографий и конфигурации по точкам |
| `calibrate_intrinsics` | параметры объектива по шахматной доске |

Полный список опций — `--help` у любой из них.

## Калибровка

Калибровка двухступенчатая, и путать ступени нельзя.

**Первая ступень - объектив.** Внутренние параметры `fx, fy, cx, cy, k1, k2`
описывают саму камеру и от её положения не зависят. Снимаются один раз.
Без них бочкообразную дисторсию не убрать: гомография переводит прямые
в прямые, а дисторсия прямые искривляет, и никакая гомография этого
не компенсирует.

```bash
./build/calibrate_intrinsics --camera 0 --cols 9 --rows 6 --square 25
```

Либо по готовым снимкам: `--images <каталог>`. Утилита сама находит доску,
уточняет углы до субпикселя и печатает невязку перепроецирования.
Требования к съёмке - в `calibrate_intrinsics --help`; коротко: не менее
десяти снимков под разными наклонами, доска должна побывать у всех краёв
кадра, иначе дисторсия на больших радиусах не определится.

Результат переносится в поле `intrinsics` нужной камеры в `config/system.json`.

**Вторая ступень - положение камеры.** Гомография переводит кадр камеры
в плоскость стола. Чтобы её получить, нужно
указать не менее четырёх точек, координаты которых известны и на кадре,
и на столе (в миллиметрах).

```bash
./build/calibrate --points config/points.json --out config/system.json
```

Формат файла точек описан в `calibrate --help`. Координаты на кадре берутся
по сырому изображению: дисторсия снимается автоматически по заданным `intrinsics`.
Утилита печатает ошибку перепроецирования — если максимум превышает 2 мм,
точки указаны неточно либо неверны параметры камеры.

Проверка самого алгоритма на сцене с известной геометрией:

```bash
./build/calibrate --from-scene
```

## Как устроен конвейер

```
источники ──► синхронизация ──► склейка ──► постобработка ──► JPEG ──► HTTP
 (по потоку     сведение        проекция     яркость,          MJPEG    браузер
  на камеру)    по меткам       на плоскость  кадрирование
                времени         стола
```

Каждый источник читает кадры в своём потоке и ставит метку времени.
Синхронизатор собирает наборы кадров, снятых примерно одновременно: якорем
служит самая поздняя метка, всё, что старше допуска, отбрасывается. Склейка
переносит кадры на общий холст по предрассчитанным таблицам, поэтому на каждый
кадр приходится только выборка и взвешенное суммирование.

### Как убирается тень от головы лазера

Голова лазера находится над плоскостью стола и потому нарушает допущение
гомографии: в зоне перекрытия камеры видят на её месте разное. Простое
усреднение смешало бы тёмную голову со столом и размазало тень по панораме.

Вместо этого в зоне перекрытия сравниваются отсчёты камер: если один заметно
темнее другого (порог `occlusionThreshold`), он отбрасывается, а переход
делается плавным, чтобы не оставлять контура. Так то, что закрыто в одном
виде, подхватывается из другого — ради этого в отчёте и ставится вторая камера.

**Допущение:** приём работает, когда перекрывающий объект темнее наблюдаемой
поверхности. Это верно для стола под освещением, но за его пределами фон темнее
головы, и там в панораме может остаться её силуэт. Отключается флагом
`stitch.occlusionRejection` в конфигурации.

## Конфигурация

`config/system.json` описывает источники, камеры, склейку, синхронизацию
и сервер. В файле достаточно указать только то, что отличается от умолчаний.

```jsonc
{
  "sources": [
    { "id": "cam_left", "type": "jpegdir", "path": "data/cam_left",
      "width": 640, "height": 480, "fps": 30, "startOffsetUs": 0 }
  ],
  "cameras": [
    { "sourceId": "cam_left", "imageWidth": 640, "imageHeight": 480,
      "intrinsics": { "fx": 430, "fy": 430, "cx": 320, "cy": 240, "k1": -0.145 },
      "homography": [ /* 9 чисел, кадр камеры -> холст */ ] }
  ],
  "stitch": {
    "canvasWidth": 1280, "canvasHeight": 720,
    "featherPx": 48,              // ширина растушёвки на стыке
    "exposureCompensation": true, // выравнивание яркости камер
    "occlusionRejection": true,   // отбраковка перекрытых участков
    "occlusionThreshold": 30,
    "threads": 0                  // 0 - по числу ядер
  },
  "sync": { "toleranceUs": 20000, "bufferDepth": 8 },
  "server": { "bindAddress": "127.0.0.1", "port": 8080, "webRoot": "web" },
  "processing": { "brightness": 0, "contrast": 1, "jpegQuality": 80 }
}
```

Порядок в `cameras` обязан совпадать с порядком в `sources`: склейка
сопоставляет их по индексу.

## Типы источников

| Тип | Назначение |
|---|---|
| `synthetic` | виртуальная сцена; работает без железа и данных |
| `jpegdir` | каталог кадров, отсортированных по имени |
| `mjpeg` | файл с потоком JPEG |
| `camera` | реальное устройство — см. `docs/HARDWARE.md` |

## Веб-интерфейс

| Адрес | Что отдаёт |
|---|---|
| `/` | страница оператора |
| `/stream.mjpg` | панорама потоком MJPEG |
| `/snapshot.jpg` | последний собранный кадр |
| `/api/status` | статистика конвейера |
| `/api/settings` | чтение и изменение настроек изображения |
| `/api/config` | текущая конфигурация |

Со страницы доступны яркость, контраст, насыщенность, качество JPEG,
кадрирование и два режима диагностики: подсветка зоны перекрытия и карта
покрытия камер (чёрный — слепая зона, синий — одна камера, зелёный — две).

## Тесты

```bash
cd build && ctest --output-on-failure
```

Три набора: математика гомографий и собственных векторов, сведение кадров
по времени, сквозная проверка склейки — метки с известными координатами на
столе обязаны оказаться в панораме там, куда их переводит расчётное
преобразование.

## Производительность

Измерено на 12-ядерной машине, две камеры 640×480, холст 1280×720:

| Стадия | Время на кадр |
|---|---|
| Склейка | 12 мс |
| Постобработка | 5 мс |
| Кодирование JPEG | 12 мс |
| **Итого** | **30 кадр/с** |

Склейка распараллелена по горизонтальным полосам холста; число потоков задаётся
параметром `stitch.threads`.
